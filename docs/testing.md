# Testing guide

Run everything: `pnpm test` (Turbo builds dependencies first). Suites are Vitest throughout.

## What is covered where

| Suite                  | Location                        | Covers                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Money & lifecycle      | `tax-domain`                    | IRS rounding, deterministic rate math; all 23 statuses, legal/illegal transitions, role permissions per transition, lock states                                                                                                                                                                                                                                                        |
| Rule config invariants | `tax-year-config`               | Bracket monotonicity, EITC parameter consistency vs published maxima, unsupported-year rejection                                                                                                                                                                                                                                                                                       |
| Federal engine         | `tax-engine-federal`            | Hand-computed 2025 scenarios: single W-2 refund; MFJ family with CTC; HoH EITC + ACTC; self-employment (SE tax, QBI, balance due); qualified-dividend preferential rates; Social Security worksheet tiers; early-distribution tax; blocking diagnostics (1099-R unresolved, Schedule C loss, missing spouse, bank validation); determinism (same input ⇒ identical result incl. trace) |
| PA engine              | `tax-engine-pennsylvania`       | Flat-rate liability, withholding balance, Schedule SP full and partial forgiveness, class rules (US-gov interest exempt, cap-gain distributions as dividends, SS/unemployment untaxed), residency and multi-state blocks, balance due                                                                                                                                                  |
| Security               | `security`                      | Envelope encryption round-trip/tamper/wrong-key, blind index, scrypt verify + policy, RFC 6238 TOTP test vector + drift window, token/recovery-code generation, masking + log scrubbing                                                                                                                                                                                                |
| Audit                  | `audit`                         | Canonicalization, chain build/verify, mutation and deletion detection                                                                                                                                                                                                                                                                                                                  |
| Validation             | `validation`                    | SSN/ITIN ranges, ABA checksum, ZIP/PSD, schema parsing incl. signature consent literal                                                                                                                                                                                                                                                                                                 |
| E-file                 | `efile-core`, `efile-providers` | Orchestrator guards (diagnostics, stale signature, duplicates, resubmit-with-fresh-signature), rejection dictionary; provider **contract tests** run identically against mock and sandbox; placeholders must refuse to operate                                                                                                                                                         |
| Forms                  | `forms-engine`                  | 1040/PA-40 line mapping vs engine results, masking (no SSN patterns in rendered HTML), watermarks, XSS escaping, snapshot hash stability/sensitivity                                                                                                                                                                                                                                   |
| Documents              | `document-processing`           | Magic-byte spoof rejection, size/empty limits, EICAR quarantine path, classification, deterministic mock OCR, verification completeness + strict currency parsing                                                                                                                                                                                                                      |
| API end-to-end         | `apps/api`                      | Full lifecycle over real routes (memory store): client → return → calculate → review (reviewer separation) → client portal sign → e-file → accepted → archived; rejection → correction (signature invalidation) → resubmission → accepted; MFA + lockout; permission denials audited; unauthorized access; direct-SIGNED forbidden; unsupported year; upload security                  |

## Fixtures

`@ghimtech/testing` provides synthetic taxpayers only — obviously fake names, fixture SSN refs, chosen amounts. **Real taxpayer data must never appear in fixtures, tests, or seeds.** Scripted provider outcomes key off fixture SSN last-4 values (`9999`/`9998`/`9997`).
